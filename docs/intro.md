## 认识 tphp {#intro}

### tphp 是什么 {#what-is-tphp}

tphp（TinyPHP 的简称）是一个 **AOT 编译器**——它把类 PHP 语法的源代码先翻译成 C 语言，再由 C 编译器（GCC / Clang / TCC）编译成 CPU 能直接执行的原生二进制文件。

这里有一个关键点要先说清楚：**tphp 不是 PHP 解释器**。它不会在程序运行时逐行解释代码，而是像 C、Rust、Go 那样，在程序运行之前就把整份源码"提前编译"成机器码。打个比方，传统 PHP 像"边看菜谱边做菜"（实时翻译执行），tphp 则像"先把菜谱整理成一本说明书，再开火"（提前编译），运行时端上来的已经是一盘做好的菜。

一行命令编译，一个二进制跑起来。下面是最小的可复现示例：

```php
class Main {
    public function main(): void {
        echo "hello tphp\n";
    }
}
```

> 每个 tphp 程序都需要一个全局命名空间（不带 `namespace` 声明）的 `class Main`，入口函数必须是 `public function main(): void`。这就像 C 的 `main()`、Java 的 `public static void main`，是程序启动的"门牌号"。

编译并运行：

```bash
tphp main.php    # 编译，产物为同目录同名可执行文件
./main           # 运行（Windows 下为 main.exe）
```

输出：

```text
hello tphp
```

就这样——不需要安装 PHP 运行环境，不需要启动虚拟机，编译出的 `main` 是一个独立可执行文件，拷到任何同系统的机器上都能跑。

### 为什么用 tphp {#why}

tphp 适合那些"想要 C 的性能、又嫌 C 写起来太累"的场景。它的三个核心卖点：

**1. 性能：AOT 编译原生二进制，无解释开销**

传统 PHP 每次运行都要先解析、再编译成字节码、最后由虚拟机逐条解释执行；tphp 则在编译期一次性把代码翻译成机器码，运行时直接跑在 CPU 上。实测中，数组遍历比传统 PHP 快 18-36 倍，方法调用近乎 0 纳秒。可以理解为"把翻译工作提前到出厂前完成，运行时只管执行"。

**2. 零运行时依赖：编译产物是独立可执行文件**

传统 PHP 命令背后是一个庞大的运行时（虚拟机、字节码缓存、数百个扩展），目标机器必须装好整个 PHP 环境才能跑。tphp 编译出的二进制是"自带行李箱"的——所有运行时逻辑（内存管理、字符串、数组、异常等）都已静态链进了可执行文件里，拷贝一个文件就能运行，目标机上不需要装任何东西。这对分发命令行工具、嵌入式场景、CI/CD 镜像瘦身都特别友好。

**3. 可直接调 C：PHPC 互操作**

tphp 内置了一套叫 PHPC 的互操作层，让你在 tphp 代码里像调普通函数一样直接调 C 函数、读 C 常量、甚至把 C 结构体当对象用。这相当于给你开了一扇"后门"——既能享受 tphp 语法的高开发效率，又能在性能瓶颈处或需要复用现有 C 库时，无缝接入 C 生态。从加密库到网络库，从数据库驱动到图形库，海量 C 代码都能直接用。

### 与 PHP / C / 其他语言对比 {#compare}

| 特性 | 传统 PHP（解释执行） | tphp（AOT） | C（手写） |
|------|------|------|------|
| 执行方式 | 运行时解释字节码 | 编译期生成原生二进制 | 编译期生成原生二进制 |
| 类型系统 | 动态弱类型，运行时可变 | 强类型，首次赋值后类型固定 | 强类型静态 |
| 运行时依赖 | 需安装 PHP 环境 + 虚拟机 | 零依赖，单文件可执行 | 零依赖，单文件可执行 |
| C 互操作 | 需写扩展（FFI 有性能损耗） | PHPC 原生互操作，零开销 | 本身就是 C |
| 开发效率 | 高，语法灵活 | 高，类 PHP 语法但需显式类型 | 低，需手动管理内存 |
| 运行性能 | 基线（1x） | 18-36x（数组 / 方法场景） | 1x+（极致优化） |

> 一句话总结：tphp 试图在"PHP 的开发效率"和"C 的运行性能"之间搭一座桥。你用类 PHP 的语法写代码，得到的是 C 级别的性能和分发体验。

### 四个心智模型 {#mental-model}

理解 tphp，需要先在脑海里建立四个和传统解释型语言不同的"心智模型"。记住这四点，后面学语法时就不会踩坑。

**模型一：编译而非解释**

传统动态语言是"边读边执行"的——你改一行代码，刷新页面立刻看到结果。tphp 不一样，它要求你先运行 `tphp main.php` 把代码编译成二进制，再去运行那个二进制。这意味着改了代码必须重新编译才能生效，但也正因为如此，程序启动时没有任何解析开销，跑起来飞快。把它当作 C / Rust 那样的"编译型语言"来理解就对了。

**模型二：类型固定**

在 tphp 里，一个变量的类型在第一次赋值时就确定下来，之后不能再换。比如 `$x = 42` 之后，`$x` 永远是整数，再写 `$x = "hello"` 会报编译错误。这和传统动态语言"一个变量先存数字、再存字符串"的灵活做法不同。好处是编译器知道每个变量的确切类型，能生成最优的机器码，并且 `===` 和 `==` 在 tphp 里是等价的——因为类型已经确定，不存在"类型相同但值相等"的歧义。

**模型三：无运行时 VM**

传统解释型语言程序运行时，背后有一个虚拟机在帮你做内存管理、类型检查、方法分派等工作。tphp 把这些工作要么挪到了编译期（如类型检查），要么直接生成等价的 C 代码静态链进二进制（如内存管理）。所以 tphp 程序运行时没有 VM 开销，但也意味着一些依赖运行时动态特性的能力（如运行时执行字符串代码、运行时加载文件、可变变量、魔术方法动态分派）在 tphp 里不可用——它们需要运行时解释器，而 tphp 根本没有解释器。需要动态行为时，用 `switch` / `match` 分支或关联数组来模拟。

**模型四：可直接调 C**

这是 tphp 区别于其他高级语言的最大特色。通过 PHPC 互操作层，你可以在 tphp 代码里用 `C->函数名(参数)` 直接调用任何 C 函数，用 `C.类型名` 直接标注 C 类型，甚至用 `#include` 引入 C 头文件。对新手来说，这意味着你不需要先把 C 库"包一层"才能用——C 生态对你而言是即开即用的。当然，调用 C 意味着你拿到了 C 的全部能力（和全部风险，比如指针用错会段错误），这部分后续在 PHPC 章节会详细讲。
